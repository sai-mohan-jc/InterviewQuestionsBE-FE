		super();

		this.name = name;

	}
	
	@Override
	public int hashCode() {
		return Objects.hash(id);

3. How to find collisions in HashMap?
   Two different keys generate the same hash bucket.
   Bucket calculation using hash&(n-1). It uses Bitwise and operator.
------------------------------------------------------------------------------------------------------------------
   
4. How HashMap works internally?

1.Internal HashMap put()
2.Generate hash using hashCode()

  Calculate bucket index using:
   hash & (n - 1)
3.Go to bucket
4.If empty → store directly
5.If collision:
  *compare keys using equals()
  *same key → replace value
  *different key → add new entry
  *normal case → almost O(1)
  *heavy collision → O(n) before Java 8-using linkedList
  *O(log n) after treeification - Red Black Tree
6.If threshold exceeds → resize HashMap

8. What is the use of Kafka and partitions. What is the consumer group?
   Kafka is an event-streaming platform used for asynchronous communication between services.
   Topics are used to store messages/events. Topics are divided into partitions for scalability, parallel processing, and better performance.
   Partitions are mainly useful when multiple instances of the same service exist within the same consumer group, because Kafka can distribute partitions  among those instances for parallel processing and scalability. 
   Consumer groups help distribute messages among multiple consumer instances and Kafka tracks offsets using consumer groups. 
   Offsets are unique message positions inside partitions used to track consumed messages. 
   Replicas are copies of partitions used for fault tolerance and high availability

Saga Orchestrator:
-------------------

This is the central coordinator.

@Service
@RequiredArgsConstructor
public class SagaOrchestrator {

    private final PaymentClient paymentClient;
    private final InventoryClient inventoryClient;

    public void startSaga() {

        try {

            // Step 1
            paymentClient.deductPayment();

            // Step 2
            inventoryClient.reserveInventory();

            System.out.println("Order Completed Successfully");

        } catch (Exception ex) {

            System.out.println("Inventory Failed");

            // Compensation Transaction
            paymentClient.refundPayment();

            System.out.println("Payment Refunded");
        }
    }
}

12.How circuit breaker works?
   A Circuit Breaker is a design pattern used in microservices to prevent a failing service from causing a cascade failure across the system.

Three States of Circuit Breaker:
--------------------------------
1. Closed State (Normal):
-------------------------

Everything is healthy.

Order Service
      |
      v
Payment Service

Requests are allowed through.

SUCCESS
SUCCESS
SUCCESS

2. Open State (Service Failing):
---------------------------------

Failure threshold reached.

FAIL
FAIL
FAIL
FAIL

Circuit opens:

Order Service
      X
Payment Service

Now:

No actual call is made.

Immediate response:

"Payment service unavailable"

or fallback response.

3. Half-Open State (Testing):
-----------------------------

After a wait period:

30 seconds later

Circuit Breaker allows a few requests.

Test Request

If successful:

Circuit -> CLOSED

If failed:

Circuit -> OPEN again

Spring Boot Example (Resilience4j):
-----------------------------------

Dependency:
-----------

<dependency>
    <groupId>io.github.resilience4j</groupId>
    <artifactId>resilience4j-spring-boot3</artifactId>
</dependency>
Service:
@Service
public class PaymentService {

    @CircuitBreaker(
        name = "paymentService",
        fallbackMethod = "fallback")
    public String makePayment() {

        throw new RuntimeException("Bank Down");
    }

    public String fallback(Exception ex) {

        return "Payment Service Temporarily Unavailable";
    }
}
Controller
@RestController
@RequiredArgsConstructor
public class PaymentController {

    private final PaymentService paymentService;

    @GetMapping("/pay")
    public String pay() {

        return paymentService.makePayment();
    }
}
Configuration:
-------------

resilience4j:
  circuitbreaker:
    instances:
      paymentService:
        failureRateThreshold: 50
        slidingWindowSize: 10
        waitDurationInOpenState: 30s

Meaning:
--------
Monitor last 10 requests
If > 50% fail
Open circuit
Wait 30 seconds
Move to Half-Open
Example Flow
Request 1 -> Fail
Request 2 -> Fail
Request 3 -> Fail
Request 4 -> Fail
Request 5 -> Fail

Failure rate:
-------------
5/5 = 100%

Threshold exceeded.

Circuit:
--------
OPEN

Next requests:
--------------
No API call made
Fallback executed
