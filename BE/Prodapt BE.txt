If we override hashcode and equals methods:

package com.learn.mapexample;

import java.util.Objects;

public class Employee {
	
	int id;
	
	String name;

	public Employee(int id, String name) {
		super();
		this.id = id;
		this.name = name;
	}
	
	
	@Override
	public boolean equals(Object o) {
		Employee e=(Employee)o;
		return this.id == e.id;
	}
	
	@Override
	public int hashCode() {
		return Objects.hash(id);
	}
	

}

3. How to find collisions in HashMap?
   Two different keys generate the same hash bucket.
   Bucket calculation using hash&(n-1). It uses Bitwise and operator.
   
4. How HashMap works internally?

1.Internal HashMap put()
2.Generate hash using hashCode()

  Calculate bucket index using:
   hash & (n - 1)
3.Go to bucket
4.If empty → store directly
5.If collision:
  *compare keys using equals()
  *same key → replace value
  *different key → add new entry
  *normal case → almost O(1)
  *heavy collision → O(n) before Java 8-using linkedList
  *O(log n) after treeification - Red Black Tree
6.If threshold exceeds → resize HashMap

7. What is the use of Kafka and partitions. What is the consumer group?
   Kafka is an event-streaming platform used for asynchronous communication between services.
   Topics are used to store messages/events. Topics are divided into partitions for scalability, parallel processing, and better performance.
   Partitions are mainly useful when multiple instances of the same service exist within the same consumer group, because Kafka can distribute partitions  among those instances for parallel processing and scalability. 
   Consumer groups help distribute messages among multiple consumer instances and Kafka tracks offsets using consumer groups. 
   Offsets are unique message positions inside partitions used to track consumed messages. 
   Replicas are copies of partitions used for fault tolerance and high availability

8. How we can confirm our message is consumed or not? 
Kafka confirms message consumption using committed offsets. By comparing the latest offset and consumer committed offset, we can identify pending messages using consumer lag.

9. What is the use of acknowledgement in kafka?
 Message processed successfully, now commit the offset.
Two types of offset commit:
1. Auto commit:
   Auto commit have some issue, if consumer methods get some exception. It's already commit offset. It treated as message delivered.
   By default auto commit is true. need to make it false.
   enable-auto-commit=false

2. Manual commit:
   Manual commit helps to send manual acknowledgement once business logic completed.
 
Ex: ack.acknowledged();

package com.learn.mapexample;

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
import java.util.stream.Collectors;

public class StreamRelated {
	
	public static void main(String[] args) {
		List<String> names = Arrays.asList("SAI");
		
		Employee e1=new Employee(1, "SAI");
		Employee e2=new Employee(2, "SAIMohan");

		List<Employee> employees = new ArrayList<>();
		employees.add(e1);
		employees.add(e2);
		
		List<Employee> fil=employees.stream().filter(e->names.contains(e.getName())).collect(Collectors.toList());
		System.out.println(fil);
		fil.stream().forEach(a->a.setName(a.getName()+"S"));
		System.out.println(fil);

	}

}
